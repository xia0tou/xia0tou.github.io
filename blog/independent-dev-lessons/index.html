开发复盘

第一次做独立开发，我踩过的七个坑

2026 年 8 月 21 日 约 2 分钟 775 字

目录

去年年底，我做了一个很小的独立产品：一个帮人整理读书笔记的小工具。上线三个月，付费用户二十几个，赚的钱不够付服务器。

但复盘下来，这三个月学到的东西，比在公司一年还多。写下来，给同样想做点什么的人。

1. 先做出来，再谈优雅

我的第一版花了一个月，搭了一套自认为很优雅的架构：分层、依赖注入、完整的测试。结果是，等它终于能跑的时候，我已经不想做了。

后来重写，两个周末上线。丑，但是活的。

能用的丑东西，永远比完美的半成品有价值。

2. 把「想法」当成需求

我以为大家都会想要「自动整理笔记」。实际上，大部分人的笔记根本没多到需要整理。

真正的需求是我在三个用户访谈里听到的那句：「我记完就再也没看过。」他们需要的不是整理，是回顾。

3. 低估了支付和合规

接支付花的时间，比写核心功能还多。个人开发者能用的通道有限，还要处理退款、发票、对账。

建议：第一版直接用手动收款（收款码 + 人工开通），验证有人愿意付钱，再考虑自动化。

4. 上线不是终点，是起点

上线那天我很兴奋，发了几条动态，然后……就没有然后了。

产品不会自己长出来。没有分发，就没有用户；没有用户，就没有反馈；没有反馈，就不知道下一步做什么。

5. 日志和错误监控要第一天就有

用户不会告诉你他们遇到了什么错误，他们只会关掉页面。

我第二周才加上错误上报，结果发现有个必现的崩溃已经存在了六天，所有 iOS 用户都卡在登录页。

6. 别急着做「平台」

我一度想做成「笔记生态」：插件、模板、社区。听着很酷，实际上我连一百个用户都没有。

先做一个有人愿意每天打开的小工具，再谈生态。

7. 重复提交这种小事，会真的出事

用户网络慢的时候会连点按钮，于是扣了两次钱。处理这个问题的代码其实很简单：

js
// 防重复提交：够用就好
const pending = new Set();

async function submit(id) {
  if (pending.has(id)) return;
  pending.add(id);
  try {
    await api.pay(id);
  } finally {
    pending.delete(id);
  }
}

这件事让我明白，独立开发里没有「小事」。每一个没想过的边界，都会以退款邮件的形式回来找你。

最后

如果让我给一年前的自己一句建议，大概是：把范围缩小一半，把上线时间提前一倍。

做小东西最大的好处不是赚钱，而是你能完整地经历一次「从想法到有人使用」的闭环。这个闭环，在公司里很难一个人走完。

至于那二十几个用户，其中有一个人给我写了很长的一封信，说这个工具帮她重新读完了三本书。那一刻我觉得，服务器钱花得挺值。
